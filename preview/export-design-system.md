# 导出报告页 — UI 设计方案

> **作者**: UI Designer · **时间**: 2026-07-27
> **改动文件**: `src/pages/ExportPage.tsx`(重写)
> **设计目标**: 统一到项目设计语言、突出 3886 条数据、强化状态语义、提升可读性

---

## 一、问题诊断

| 问题 | 原因 | 影响 |
|---|---|---|
| 整页深灰背景 | ExportPage 用 `bg-slate-900` 而项目其他页面用 `bg-white` | 与侧边栏、DashboardPage 严重脱节 |
| 侧边栏 "xport" 被截断 | 浅色侧边栏被深色主区域从视觉上"压住",看起来像被截断 | 导航菜单不完整,误导用户 |
| 3836 这个数字不突出 | 用普通 2xl 字号,跟正文大小差不多 | 数据没有视觉重点 |
| 状态徽章颜色对比差 | success / failed / screened 全部用红色 | 用户无法快速区分投递状态 |
| 日期筛选不直观 | 没有快捷范围,只能手动选日期 | 操作路径长 |
| PDF 背景色 `slate-900` | 跟主区域风格冲突,PDF 也不适合深色 | 导出文档不专业 |

---

## 二、设计原则

1. **设计系统一致性**: 100% 复用项目的「暖陶土 + 编辑数据风」,跟 `Sidebar`、`DashboardPage`、`TodayPage` 完全统一
2. **数据即主角**: 3886 条记录是核心数据,大号 `font-display` 衬线字体 + 暖陶土色突出
3. **状态语义化**: 成功(绿) / 系统筛选(琥珀) / AI 低分(红) / 待处理(灰),颜色一眼可辨
4. **信息层级清晰**: Hero 数字 → 统计卡片 → 状态分布条 → 表格
5. **可读性优先**: 表格行宽松、序号等宽、列宽合理

## 五、关键设计决策

### 1. 数据统计卡片(新增)

**为什么**: 之前只显示 3886 一个数字,看不出成功/失败/筛选的比例。
**怎么做**: 4 个并排卡片,各自带 icon + 进度条 + 百分比,信息密度高但不拥挤。
**效果**: 用户一眼能看出"成功率 13%" "筛选率 5%" "AI 拦截 0%"。

### 2. 状态分布条(新增)

**为什么**: 表格里每行都有状态徽章,但缺乏全局视角。
**怎么做**: 在表头加一条横向堆叠条,按比例显示各状态占比,右侧配图例。
**效果**: 直观看出"投递成功占大头,系统筛选次之,AI 拦截几乎没有"。

### 3. 快捷日期范围(新增)

**为什么**: 3886 条数据里 7 月的占大头,用户常看"最近 7 天 / 30 天"。
**怎么做**: 在筛选卡片右上角加 4 个 tab(今天 / 7天 / 30天 / 全部),点击自动设置起止日期。
**效果**: 一键切换时间范围,不用手选日期。

### 4. 序号等宽(细节)

**为什么**: 001 / 002 / 003 比 1 / 2 / 3 更整齐,杂志感更强。
**怎么做**: `font-mono` + `tabular-nums` + `padStart(3, '0')`。
**效果**: 视觉对齐,扫描更快。

### 5. 浏览器用 emoji 图标(细节)

**为什么**: 之前只是文字"火狐/谷歌",不够直观。
**怎么做**: 🟢 Chrome / 🟠 Firefox,emoji + 文字组合。
**效果**: 一眼看出浏览器来源,与状态徽章视觉一致。

### 6. PDF 背景色修复

**之前**: `backgroundColor: '#0f172a'` (slate-900)
**现在**: `backgroundColor: '#faf9f6'` (项目主背景)
**原因**: PDF 是给别人看的,深色背景打印不友好且与品牌不符。

## 八、修复的 bug

在重写过程中发现并修复了:

1. **`animation-fill-mode: backwards` 覆盖 `forwards`**
   - 现象: 所有 `animate-in` 元素动画结束后回到 opacity 0
   - 原因: `forwards`(CSS 类) + `backwards`(inline style) 冲突
   - 修复: 删除 inline `style={{ animationFillMode: 'backwards' }}`
