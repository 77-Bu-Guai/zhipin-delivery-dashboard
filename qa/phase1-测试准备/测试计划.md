## 一、测试范围

### In Scope（必测）
1. 全局导航与路由（8 个页面）
2. Dashboard 仪表盘（5 类统计 + 图表）
3. 投递明细 JobDetail（加分/扣分/AI 评分解析）
4. 扣分分析 Deductions
5. 今日 Today（今日维度）
6. 分类 JobCategory / CategoryDetail（20 大类）
7. 导出 Export（PDF 原生 print）
8. AI 助手 + AI 接口配置面板（3 供应商 / 测试连接 / 持久化 / 导入导出）
9. AI 中继 `/ai-proxy` + `/mimo`（含安全红线）
10. 数据层 SQLite / extension-data.json / dataLoader（增量、tracker）
11. 评分体系（-5000 致命项 / 阈值分档）
12. boss-extension 插件（自动投递 / 滑块上限 300 / 过滤）

### Out of Scope（本版不测）
- 尚未实现的「团队协同 / 多账号」等规划功能
- 第三方模型服务本身的稳定性（只测接入层，不测模型质量）

## 二、测试环境

| 项 | 配置 |
|----|------|
| 前端 | `npm run dev`（Vite，含 `/ai-proxy` 中继）|
| 桌面端 | Electron 打包（`npm run dist`）单独跑一轮兼容 |

## 三、测试策略

- **功能测试**：按 `测试用例.md` 逐用例执行，覆盖 正常 / 边界 / 异常 / 权限 / 兼容 / 回归 六类场景。
- **兼容测试**：Chrome / Firefox / Electron 打包三端各跑一遍 AI 配置与导出。
- **安全测试（资深开发重点）**：Key 不进打包产物、不进 git；中继只转发不落盘。
- **性能测试**：5000+ 条数据下仪表盘渲染、打印不卡死。
- **回归测试**：每次改动后跑受影响模块的回归清单（模板见 `templates/回归验证清单模板.md`）。

## 六、风险提示（提前暴露）

| 风险 | 影响 | 应对 |
|------|------|------|
| AI 中继依赖 dev server，纯静态/Electron 下行为不同 | 线上/打包后可能连不上 | 兼容测试单列一轮，验证回退直连 |
| 配置持久化三重 + 服务端落盘冲突 | 切浏览器/清缓存丢配置 | 用例 TC-809 专门验冲突取新 |
| 评分阈值与提示词不同步 | 统计失真、误判 | 用例 TC-1102/1103 锁死一致性 |
| 海量数据渲染 | 卡顿/崩溃 | 用例 TC-204/1003 压边界 |
| PDF 已知 jsPDF 中文乱码坑 | 回退风险 | 用例 TC-702 锁死原生 print |
