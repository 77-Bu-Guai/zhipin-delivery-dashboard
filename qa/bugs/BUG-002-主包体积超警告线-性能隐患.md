# BUG-002 主 JS chunk 896KB 超 500KB 警告线，首屏性能隐患

- Bug ID：BUG-002
- 标题：构建产物主 chunk 896KB（gzip 239KB），超过 500KB 警告线
- 来源：测试（构建门禁观察项）
- 发现日期：2026-08-01
- 报告人：资深开发（吴八哥）
- 严重程度：S3（性能/体验，不阻断功能）
- 优先级：P2
- 是否阻断上线：否
- 关联需求/PRD/用例：研发质量Checklist G（性能）、Premium 标准「首屏 < 1.5s」
- 研发负责人：戚锦豪
- 当前状态：已修复（待验收）

## ★ 复现环境
- 命令：`npm run build`
- 结果：`✓ built in 17.78s`，但报 `(!) Some chunks are larger than 500 kB`

## ★ 复现步骤
1. `npm run build`
2. 观察输出：`dist/assets/index-Dhsfg-jf.js  896.23 kB │ gzip: 238.96 kB`

## ★ 实际结果
单 chunk 896KB（gzip 239KB），触发 Vite 体积警告；recharts / xlsx / better-sqlite3 等均为重依赖，全部打进主包。

## ★ 期望结果
按路由/依赖做 code-split（dynamic import / manualChunks），主包控制在合理范围，保障首屏加载 < 1.5s。

## 影响范围
- 首屏加载变慢，弱网/低配机器体验下降；不利于「premium」定位。

## —— 研发定位（修复前填）——
- 可能原因（带依据）：未在 `build.rollupOptions.output.manualChunks` 拆分 vendor；图表(xlsx/recharts)、DB(better-sqlite3)、AI 模块同包。依据：构建输出仅一个主 index js。
- 排查路径：① 路由级 `React.lazy` 拆分页面 → ② 把 xlsx/recharts 等重依赖单独 manualChunk → ③ 复测体积与首屏。
- 待补充信息：需你确认是否接受引入 code-split（会改变少量加载行为）。

## 根因（修复后填）
主包 896KB 的根因：
1. `xlsx`（SheetJS ~430KB）被 `ExportPage.tsx:10` 与 `TodayPage.tsx:8` **静态 import**，打进主包；
2. `build.rollupOptions.output.manualChunks` 未配置，所有 node_modules 与业务代码混在一个 chunk。
（注：原描述提到的 recharts / better-sqlite3 实际未进入 bundle——recharts 全项目无 import，better-sqlite3 仅 Node 端脚本用，已 tree-shake 排除。）

## 修复说明（修复后必填）
- **xlsx 改动态 import**：`ExportPage` / `TodayPage` 的导出函数改为 `const XLSX = await import('xlsx')`，xlsx 仅在用户点「导出」时按需加载，踢出主包（`src/pages/ExportPage.tsx`、`src/pages/TodayPage.tsx`）。
- **vite manualChunks 拆分 vendor**（`vite.config.ts`）：`xlsx` → 独立 chunk；`react/react-dom/react-router/zustand` → `react-vendor`；`lucide-react` → `icons`。
- 影响范围：仅改变构建产物的分块方式，运行行为不变；导出功能经阶段①浏览器实测（TC-702/TC-801~804）确认可用。

## 回归结论
- 构建：`npm run build` 通过，主包 `index.js` 由 **896KB → 396KB**（gzip 239KB → 75KB），**已低于 500KB 红线**；
- `xlsx` 独立为 430KB 的按需 chunk；`react-vendor` 216KB；**500KB 体积警告已消除**；
- 门禁：`tsc 0 errors`、`eslint 0 errors`（仅 4 个非阻断 warning，与修复前一致）。
- 遗留项：构建出的 `index.html` 内含 10.8MB 的 `extension-data.json`（embed-data 插件），是比 JS 体积更大的首屏隐患，已单独立项 **BUG-004**，本轮未动（涉及 Electron 离线架构，需你拍板）。
