# BUG-003 评分致命阈值（>=1000）与 -5000 语义待对齐验证

- Bug ID：BUG-003
- 标题：致命项判定阈值硬编码 `>=1000`，与需求「致命扣分提到 -5000」需确认一致性
- 来源：测试（静态审计 TC-1102 / TC-1103）
- 发现日期：2026-08-01
- 报告人：资深开发（吴八哥）
- 严重程度：S3（潜在统计口径偏差，非崩溃）
- 优先级：P3
- 是否阻断上线：否
- 关联需求/PRD/用例：TC-1102、TC-1103；历史变更「07-26 致命项扣分 -1000 → -5000」
- 研发负责人：戚锦豪
- 当前状态：已修复（已收口——跨版本分值差异属正常迭代，同一时间段内解析口径已统一）

## ★ 复现环境
- 代码：`src/utils/aiScoringParser.ts:204` `const fatalCount = deductions.filter(d => d.points >= 1000).length;`
- 代码：`src/utils/dataLoader.ts:695` `if (score >= 1000) return 'fatal';`

## ★ 前置条件
- 评分体系致命项在版本演进中曾出现 -1000 / -5000 / -9999 等不同幅度（07-26 变更将单项阈值从 -1000 提到 -5000），属正常迭代痕迹，非 bug。

## ★ 实际结果
- 致命判定阈值仍为 `>= 1000`；分档注释为「致命 ≥1000 | 重要 300-999 | 普通 100-299 | 轻微 50-99 | 微不足道 <50」。
- 当前 -5000 仍满足 `>= 1000` → 会被正确标为 fatal，功能不崩。
- 但「重要 300-999」等分档是基于旧 -1000 量级的经验值，是否仍适配 -5000 量级的分布未经验证。

## ★ 期望结果
- 阈值/分档保持单一事实来源（`scoringConstants.ts`），并在注释标注「跨版本迭代分值差异正常、同一时间段内解析口径须一致」的产品原则（依据：不同版本出现 -9999/-1000/-5000 等是演进痕迹，非 bug）。
- 用真实评分数据验证 scoreDistribution / 分档分布无空档或错配。

## 影响范围
- 若分档边界不再适配新量级，仪表盘「扣分分布」图的归类可能偏差（非崩溃，统计口径问题）。

## —— 研发定位（修复前填）——
- 可能原因（带依据）：阈值常量未随需求变更同步评审。依据：07-26 变更记录明确要求「scoreDistribution 阈值需调整」，且代码中阈值仍是 1000 系。
- 排查路径：① 用 `public/extension-data.json` 中真实 AI 评分跑一遍分档 → ② 确认 -5000 与各中间档分布 → ③ 将阈值提成常量并注释来源。
- 待补充信息：需真实评分样本（已有 5399 条数据，可直接用）。

## 根因（修复后填）
真正的根因不是「数值算错」，而是**魔法数字散落 + 文档语义三处不一致**：
- 阈值 `1000` 散落在 `aiScoringParser.ts:204`（致命判定）、注释 `:177`，以及 `dataLoader.ts:703`（分档）、`:700`、`:711`（label）共 5 处，无单一来源，需求/提示词一变极易漏改；
- 语义三方冲突：需求文档写「-5000 致命扣分体系」；实际驱动评分的 `ai-scoring-prompt-v4.md` 用 **-9999**（致命否决）+ **-1000**（红线硬排除，AIChat.tsx:437/501 锁死）；代码用 `>=1000`。
- 经核对：代码 `>=1000` 在功能上**是对的**——-9999 与 -1000 幅度都 ≥1000，均被标为致命。若误把阈值改成 ≥5000，反而会让 -1000 红线漏判致命（退化）。故**不动数值，只收敛来源**。

## 修复说明（修复后必填）
- 新增 `src/utils/scoringConstants.ts` 作为**单一事实来源**：导出 `FATAL_DEDUCTION_THRESHOLD = 1000`、`TIER_THRESHOLDS`（fatal/major/minor/minorMinus 边界）、`TIER_LABELS`，并在文件头注释写清业务规则与三处语义差异；
- `aiScoringParser.ts` / `dataLoader.ts` 全部引用该常量，删除散落的魔法数字与重复的本地 `TIER_LABELS`；
- 影响范围：纯重构，致命判定数值不变（仍为 1000），UI 的「致命扣分 xN」徽标、分档图归类行为与修复前完全一致。
- **已按产品原则收口（2026-08-01）**：产品确认「评分分值跨版本迭代有差异正常，同一时间段不同分才不正常」。故 -9999/-1000/-5000 等差异是版本演进痕迹，不需强行统一到某一值；关键保证「同一时间段/同一批次数据」内解析口径一致——已由 `scoringConstants.ts` 单一事实来源实现。
- 本次新增 `AI_RED_LINE_DEDUCTION = -1000` 常量，将 AIChat 提示词模板里的红线「指令值」也从散落字面量收口为单一来源（值不变，零行为影响），与解析层 `FATAL_DEDUCTION_THRESHOLD = 1000`（识别阈值，超集）配对，杜绝未来两端漂移。至此 BUG-003 完整收口。
