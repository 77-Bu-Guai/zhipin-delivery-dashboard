# 版本验收报告模板

> 由测试/产品在做版本验收时汇总。复制为 `phase1-测试准备/../验收-<版本号>.md` 或 `qa/` 下。
> 输出结论需产品 + 资深开发双签（尤其涉及阻断项时）。

```markdown
# 版本验收报告 · v＜版本/日期＞

- 验收日期：YYYY-MM-DD
- 验收人：＜产品 / 测试＞
- 资深开发确认：＜签名/确认＞

## 一、测试通过情况
| 维度 | 总数 | 通过 | 失败 | 阻塞 | 通过率 |
|------|------|------|------|------|--------|
| 用例执行 | | | | | |
| 需求覆盖 | | | | | |

## 二、未解决 Bug 清单
| Bug ID | 严重度 | 优先级 | 状态 | 是否阻断 |
|--------|--------|--------|------|----------|
| BUG-XXX | S2 | P1 | 修复中 | 否 |

## 三、阻塞项 & 延期风险
- 阻塞项：＜列明，含责任人+预计解除时间＞
- 延期风险：＜需求变更 / 依赖未就绪 / 资源不足＞

## 四、上线风险清单
- 数据安全：＜SQLite 迁移/增量是否有损＞
- 兼容性：＜Electron 打包 vs 浏览器差异＞
- 外部依赖：＜AI 中继 / 第三方 Key 可用性＞

## 五、验收结论建议
- [ ] 通过，可上线
- [ ] 有条件通过（遗留项见上，需产品书面接受风险）
- [ ] 不通过（阻断项未解）

## 六、遗留问题（转下版 / 建事项）
| 遗留项 | 类型（Bug/需求） | 目标版本 |
|--------|------------------|----------|
| ＜＞ | ＜＞ | ＜＞ |
```

## 使用提醒

- 验收结论需上传项目资料库，遗留问题**必须**转为新 Bug 或下版需求，禁止「口头带走」。
- 存在任一阻断标准命中项（见 README 第四节）时，结论只能是「不通过」或「有条件通过（双签）」。
