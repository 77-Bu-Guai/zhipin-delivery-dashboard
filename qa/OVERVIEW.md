# QA 测试与缺陷协同工作流 · 交付总览

> 日期：2026-08-01
> 目标：为 BOSS 投递分析项目建立「测试准备 → Bug 反馈 → 研发定位 → 修复验证 → 测试验收 → 质量复盘」六阶段全生命周期，并嵌入资深开发的质量把关。

## 本次交付内容

### 1. 流程与规范
- `qa/README.md`：六阶段流程、角色职责、严重程度/优先级 rubric、**阻断上线 6 条标准**、提醒事项落地、文件结构。
- `qa/研发质量Checklist.md`：资深开发评审与上线门禁（自动化门禁红线、安全密钥、AI 配置持久化、数据层、评分体系、导出兼容、评审软要求）。

### 2. 五阶段可复用模板（`qa/templates/`）
- 测试用例模板、Bug 单模板、回归验证清单模板、验收报告模板、质量复盘模板。
- 每个模板字段对齐结构化强制要求（复现环境/步骤/实际/期望/附件/影响范围/根因依据等）。

### 3. 阶段① 测试准备实质产出（`qa/phase1-测试准备/`）
- `测试计划.md`：范围（12 模块 in scope）、环境、策略、负责人、验收标准、风险提示。
- `测试用例.md`：**12 模块 / 55 条用例**，覆盖 正常/边界/异常/权限/兼容/回归 六类场景，P0 用例已标红为上线阻塞项。
- `风险与执行清单.md`：风险关注点 + 按 P0/P1/P2 分层的执行清单 + 执行记录栏。

### 4. Bug 入口
- `qa/bugs/BUG登记总表.md`：状态机 + 索引表，阶段②起即用作 Bug 归档与追踪。

## 关键决策
- 把「资深开发质量把关」落成两份硬资产：README 的阻断标准 + 研发 Checklist 的门禁清单，而非口头要求。
- 测试用例全部基于项目真实功能（AI 3 供应商配置、SQLite 唯一源、5 类统计、-5000 致命评分、PDF 原生导出、插件滑块 300 等），非通用空壳。
- 当前单人兼角，文档中显式标注负责人，避免「我以为你测了」。

## 后续动作
1. 按 `风险与执行清单.md` 的 P0 清单逐条执行，失败即开 Bug 单入 `bugs/`。
2. 阶段②～⑥ 触发时引用对应模板，复盘结论回写 `研发质量Checklist.md`。
3. 每次改动跑 `npm run check` + `npm run build` 作为门禁（README 第四节第 5 条）。
