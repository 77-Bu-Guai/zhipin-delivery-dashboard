## 评分顺序（必须严格按此顺序，命中即停止检查更轻的项）
1. 先查「致命否决」（命中→直接返回-9999，不继续）
2. 再查「扣分项」（逐项累加）
3. 最后查「加分项」（逐项累加）
4. 总分 = Σ加分 - Σ扣分

## 边界规则
- 未提及不加减分；模糊措辞不处理；名称与描述冲突以描述为准
- 一处匹配多项分别计分不互斥；严禁推定（JD没写不能脑补）
- "抗压"单独出现不扣分，必须有明确加班暗示词（996/大小周/接受加班/弹性工时）搭配才扣
- 小公司判断：<50人+未融资+结合其他红旗综合判断
- ToB技术销售判据：JD有"解决方案销售"/"产品演示"/"技术方案"/"售前支持"→ 不触发纯销售扣分，触发TOB销售加分
- 硬件岗判据：PCB/嵌入式/FPGA/射频/结构设计→触发；硬件PM/硬件测试→不触发

### 输出格式
```json
{
  "reason": "一句话总结评分理由",
  "negative": [
    { "reason": "扣分原因（简洁，不超过15字）", "score": 扣分值 }
  ],
  "positive": [
    { "reason": "加分原因（简洁，不超过15字）", "score": 加分值 }
  ]
}
```
注意：
- negative 和 positive 中的 score 都是正数（系统自动计算总分 = Σpositive - Σnegative）
- 不要输出 (0分) 项 —— 如果某项检查不匹配，不写入结果
- 总分低于20分将过滤掉
