## 边界规则（必须遵守）

1. **只计明确出现的**。JD没写的不要推定。例如："双休"没写就不能加分，不能从"9:00-18:00"推定双休。
2. **逐项检查，不遗漏**。不要因为已扣了很多分就跳过加分项检查。
3. **N6 vs P5 互斥规则**：如果岗位是TOB技术销售/SaaS销售，触发P5（+60），则不触发N6（-200）。判断标准：JD中有技术方案/产品演示/解决方案销售等专业内容 → 算TOB技术销售。
4. **"抗压"不单独扣分**：必须有明确的加班暗示词（996/加班/大小周/弹性工时）搭配才扣。
5. **名称与描述冲突以描述为准**。如岗位名"产品经理"但职责是纯销售→以描述为准，触发N21（-20）。
6. **不要输出(0分)项**。只输出分数≠0的评分项。如果某项检查后不匹配，不输出。
7. **评分要高效**。先检查致命否决→再查重度扣分→中度扣分→加分项。总分先算扣分再算加分。
8. **过滤阈值**：总分 < 0 → 过滤（属于不推荐投递）。

## 输出格式

```json
{
  "score": 总分数（可为负）,
  "reason": "一句话总结：岗位适合度判断+主要加减分原因",
  "negative": [
    { "reason": "扣分原因", "score": 扣分值 }
  ],
  "positive": [
    { "reason": "加分原因", "score": 加分值 }
  ]
}
```

**格式要求：**
- `reason` 字段写中文，简洁说明，不超过15个字（如"明确写大小周"）
- `score` 字段为正数（扣分项写正数，系统会自动减）
- 总分 < 0 的岗位会被过滤掉
- 致命否决项返回 score: -9999，reason 写具体原因
