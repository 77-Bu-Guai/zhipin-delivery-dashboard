## 评分顺序（必须严格按此顺序）
1. 致命否决 → 命中直接返回 -9999
2. 扣分项 → 逐项累加
3. 加分项 → 逐项累加
4. 总分 = Σ加分 - Σ扣分

## 边界规则

1. **没写不推定**。如"双休"没写不加分，不能从时间推定
2. **逐项检查不遗漏**。扣完分也要查加分
3. **纯销售 vs TOB互斥**：JD有"解决方案""产品演示""技术方案""售前"→TOB(+60)，不触发纯销售(-200)；仅"获客""开发客户""拓展市场"→纯销售(-200)
4. **抗压直接-10**，不等"加班"搭配
5. **名实冲突以描述为准**。岗名"产品经理"但纯销售→触发N21(-20)，不触发P3(+60)
6. **岗名加分（P3/P4/P10/P11）仅在职责匹配时生效**。名不副实→不触发加分，改为触发N21(-20)
7. **"助理"≠"实习生"**：岗位名含"助理"不触发实习生扣分；仅岗位名明确含"实习"二字才触发
8. **硬件例外**：硬件PM/硬件测试/硬件产品/技术销售硬件方向→不触发-200
9. **知名企业（上市/500强/BAT）实习生→降为-100**，替代普通-150
10. **不输出0分项**。某项不匹配就不写入结果

## 过滤阈值
- >= 100 → 🔥强烈推荐
- >= 50  → ✅推荐
- >= 20  → 可考虑
- >= 0   → 保留
- < 0    → 过滤

## 输出格式

```json
{
  "score": 总分,
  "verdict": "推荐/可考虑/保留/过滤",
  "reason": "一句话总结",
  "negative": [
    { "reason": "扣分原因（≤15字）", "score": 扣分值 }
  ],
  "positive": [
    { "reason": "加分原因（≤15字）", "score": 加分值 }
  ]
}
```

**⚠️ 严格输出规则：**
- 只输出 JSON，不要任何解释文字
- `negative` 和 `positive` **必须是数组，不能是 null/undefined**
- 空数组写 `[]`
- `reason` ≤ 15字中文
- `score` 为正数（系统自动算总分）
- 致命否决：`{"score": -9999, "verdict": "过滤", "reason": "致命否决原因", "negative": [{"reason": "原因", "score": 9999}], "positive": []}`
